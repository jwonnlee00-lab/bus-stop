# 트램 정거장 추정 좌표 시험

공식 위치도의 승강장 형상과 위경도가 있는 지도를 대조해 정거장 중심을 추정하는 방법을 211번과 218번에 먼저 적용했다. 현재 CSV는 **시험 2건**이며 45개 정거장 전체 자료가 아니다. 정부청사는 도면과 지도의 대응점을 이용해 추정 좌표를 기록했고, 대전복합터미널은 도로 구간만 확인돼 좌표를 비워 뒀다. 전체 확대는 사용자 검토 후 진행한다.

## 자료와 기준일

정거장 번호와 명칭은 [대전광역시 고시 제2025-249호](https://www.daejeon.go.kr/djTram/notify/normalBoardDetail.do?boardId=djTram_0001&menuSeq=6724&ntatcSeq=1500763152), 2025-10-24자 확정 고시를 기준으로 한다. 218번은 병기 명칭을 포함해 `정부청사(서구청·둔산경찰서·을지대병원)`으로 기록했다. PDF의 글자 사이 공백과 가운데점 표기는 읽기 쉽게 정리했다.

위치는 [공식 상세 위치 공지](https://www.daejeon.go.kr/djTram/notify/normalBoardDetail.do?boardId=djTram_0001&menuSeq=6724&ntatcSeq=1464065145)의 보관된 첨부 PDF를 사용했다. 공지 제목은 `2025.12.`이지만 현재 보관본의 생성·수정 메타데이터와 첨부 경로는 2026-10-15다. 2025년 12월 당시 첨부와 동일한지 확인한 결과는 아니다. 211번은 PDF의 물리적 13쪽, 218번은 20쪽이다. 확정 명칭은 각각 명칭 고시 1쪽과 2쪽에서 확인했다.

원본은 저장소 밖 `../tram-investigation/sources/station_locations.pdf`, `../tram-investigation/sources/station_names.pdf`에 있다. 위치 PDF SHA-256은 `285e1c10c9227dcdb61778a6e4b0f0b9e04b1e798ae6da1d9b68f21e58e89b98`, 명칭 PDF는 `44bba0777da7ac514b222a3236846e44c9df4e9629abd884b690fd6fc7fddb56`이다. 재다운로드 시 해시가 다르면 같은 도면으로 취급하지 말고 다시 검토해야 한다.

지도 근거는 OpenStreetMap의 도로·건물 형상과 각 꼭짓점의 WGS84 좌표다. [OSM의 좌표계 설명](https://wiki.openstreetmap.org/wiki/Converting_to_WGS84)을 확인했으며, Overpass API 응답 원본·쿼리를 `sources/tram_pilot/`에 보관했다. 조회일은 2026-10-21이며 최초 응답의 OSM 데이터 시각은 `2026-10-21T00:52:54Z`다. 지도는 시청의 공식 측량 성과가 아니라 OSM 기여자의 지도다.

지도 형상과 이를 이용한 좌표 자료에는 **© OpenStreetMap contributors, ODbL** 출처를 표시한다. [OSM 저작권·라이선스](https://www.openstreetmap.org/copyright)와 [ODbL](https://opendatacommons.org/licenses/odbl/1-0/)을 함께 제공한다. 공식 도면은 대전광역시 자료다.

## 추정 방법

주소나 시설물 검색 결과를 정거장 좌표로 복사하지 않았다. 공식 위치도의 도로 배치·건물 외곽을 실제 위경도가 포함된 지도 형상과 대조하고, 도면 픽셀과 지도 좌표의 대응점을 직접 기록했다. CAD X/Y는 사용하지 않았다.

정부청사에서는 PDF를 가로 3,200픽셀로 렌더링한 뒤 `(1655, 745, 3065, 1885)` 영역을 잘랐다. 이 잘린 이미지의 왼쪽 위가 픽셀 원점이며, x는 오른쪽, y는 아래로 증가한다. `plan_218.png`와 `pilot_inputs.json`에 이미지 및 모든 수동 판독값이 있다.

대전둔산경찰서 건물 남서 모서리, 삼성생명 건물 남서 모서리, KT 건물 북서 모서리를 적합점으로 사용했다. 건물 이름이 같은 장소를 찾는 데서 끝내지 않고, 도면과 지도에 보이는 외곽의 모서리를 대응시켰다. OSM에서 경찰서 건물은 이름 태그가 없어 도면의 U자형 외곽·위치 관계로 식별했다. 이 식별은 수동 판독이며 측량 기준점 인증을 받은 것은 아니다.

| 역할 | 도면 픽셀 x/y | OSM way | OSM node |
|---|---|---|---|
| 적합: 경찰서 남서 | 197 / 239 | 502541396 | 4929876499 |
| 적합: 삼성생명 남서 | 1001 / 316 | 502541394 | 4929876486 |
| 적합: KT 북서 | 95 / 995 | 502531462 | 4929822463 |
| 검사: 경찰서 남동 | 423 / 239 | 502541396 | 4929876497 |
| 검사: 삼성생명 남동 | 1237 / 315 | 502541394 | 4929876489 |
| 검사: KT 북동 | 403 / 995 | 502531462 | 4929822464 |
| 검사: 한국은행 북서 날개 | 620 / 990 | 502531463 | 4929822484 |
| 검사: 한국은행 본관 북동 | 1223 / 989 | 502531463 | 4929822481 |

OSM의 WGS84 좌표를 이 구역 중심의 미터 단위 방위정거도법으로 옮겨 3점 아핀 변환을 계산했다. 이 투영은 이미 좌표계가 알려진 지도 좌표의 거리 계산을 위한 것이며, 미확인 CAD에 좌표계를 부여한 작업이 아니다. 적합에 쓰지 않은 5점의 차이를 계산한 뒤 도면 승강장 영역의 중심을 WGS84로 되돌렸다.

218번 도면의 회색 승강장 두 영역을 각각 `(578,560)~(892,584)`, `(578,614)~(892,638)`의 사각형으로 판독했다. 둥근 끝은 대칭으로 단순화했다. 두 영역을 합친 면적가중 중심 `(735,599)`를 정거장의 단일 대표점으로 정의했다. 따라서 `platform_pair_centroid`는 양방향 승강장 영역의 중심이며, 어느 한쪽 승강장 위의 승차점이나 출입구가 아니다. 두 영역 사이 선로 쪽에 놓일 수 있다. 도면의 정거장명 글자나 붉은 위치 표시점은 대표점으로 사용하지 않았다.

## 시험 결과

| 번호 | 정거장 | 등급 | 위도 | 경도 |
|---|---|---|---:|---:|
| 211 | 대전복합터미널 | B | 빈 값 | 빈 값 |
| 218 | 정부청사(서구청·둔산경찰서·을지대병원) | A | 36.357463 | 127.381497 |

정부청사의 적합에 쓰지 않은 5점 차이는 2.86, 2.11, 2.42, 9.79, 7.62m다. RMSE는 5.87m, 최대는 9.79m다. 검사점 3개는 적합에 사용한 건물의 다른 모서리이고, 2개는 적합에 쓰지 않은 한국은행 건물이다. 모두 독립적인 측량 기준점으로 검증한 것처럼 해석하면 안 된다.

시험 스크립트는 최대 검사점 불일치가 15m를 넘으면 좌표 출력을 중단한다. 15m는 이번 시험의 내부 일관성 확인을 위한 임시 기준이며, 공식 정확도 기준이나 절대 위치 오차의 상한이 아니다. 전체 확대 전에 대표점 정의와 함께 검토할 항목이다.

KT 대신 한국은행 본관 북동 모서리를 넣는 대안 적합에서 대표점은 3.61m 이동했다. 동일한 저장 입력을 사용해 계산을 다시 실행했을 때 CSV 결과가 같음을 확인했다. 이는 계산의 재현성과 지도·도면의 내부 정합성을 확인한 결과다. OSM의 절대 위치 오차, 도면 배경도의 왜곡, 모서리·승강장 경계의 수동 판독 오차, 설계 변경은 별도로 남아 있다. 소수점 6자리 표기는 계산 재현을 위한 것으로 그 수준의 정확도를 뜻하지 않는다.

대표점은 적합 3점의 삼각형에서 약간 벗어나므로 소폭 외삽에 해당한다. 삼각형 경계까지의 거리는 검증 JSON의 `distance_to_fit_triangle_m`에 기록했다. 삼각형 밖이라는 점은 추가 불확실성이며, 도면 남동쪽의 한국은행 검사점을 함께 확인한 이유다. 새 정거장에는 가능한 한 승강장을 둘러싸는 대응점을 확보하고, 적합·검사점 모두 확보하지 못하면 B 또는 C로 남겨야 한다. 검토 이미지는 `sources/tram_pilot/218_review.png`이며, 파란 선은 OSM 건물 외곽, 초록 사각형은 판독한 승강장 영역, 자홍색 십자는 그 중심이다.

대전복합터미널은 공식 도면에서 한밭대로의 승강장 형태를 볼 수 있고 지도에서 도로망을 확인했지만, 현재 OSM 자료에는 도면의 주변 건물·세부 교차로와 확실히 대응시킬 형상이 부족하다. 정부청사와 같은 방식으로 검사 가능한 변환을 만들지 못했으므로 B로 두고 좌표를 기록하지 않았다. 동서대로의 기존 버스정류장 좌표, 터미널 건물 좌표, 인근 도로 주소는 대체 좌표로 쓰지 않았다. 더 상세하고 좌표가 있는 지도에서 재검토해야 한다.

## 등급과 번호 검사

`confidence`는 확률이 아닌 검토 상태다.

| 등급 | 판정 기준 | 이번 시험 |
|---|---|---:|
| A | 승강장 영역을 식별하고 지도와 위치 교차 검증 | 1 |
| B | 도로 구간은 확인했으나 승강장 중심을 검증하지 못함. 좌표는 비움 | 1 |
| C | 도로·승강장 위치를 확인할 수 없음. 좌표는 비움 | 0 |
| 미검토 | 아직 작업하지 않음. C로 간주하지 않음 | 43 |

CSV에는 211·218번 2개가 있으며 중복은 0건이다. 전체 목표 201~245번과 비교하면 43개가 아직 CSV에 없다. 따라서 **45개 전체 번호 완전성 검사는 아직 통과한 상태가 아니다**. `validation.json`의 `station_numbers_missing_from_45`에 미검토 번호를 기록했다. 전체 확대 시 201~210, 211~220, 221~230, 231~240, 241~245의 순서로 검토하며 기존 시험 2건도 자료 변경 여부를 확인한다.

현재 교차 검증하지 못한 위치는 211번 승강장 중심과 미검토 43개다. 218번도 실제 지상 위치를 측량하거나 현장 확인한 결과는 아니다. 두 시험 결과만으로 나머지 정거장에도 같은 방법이 모두 적용된다고 가정하지 않는다.

## 재현 방법

선택한 픽셀·승강장 영역과 OSM 응답은 저장돼 있어 네트워크 요청 없이 계산할 수 있다.

```sh
python -m pip install -r requirements-tram.txt
python scripts/estimate_tram_pilot.py --output tram_pilot_recheck.csv --report tram_pilot_recheck.json
```

스크립트는 출력 파일이 이미 있으면 중단한다. `sources/tram_pilot/pilot_inputs.json`에는 수동 대응점과 판독 규칙, `validation.json`에는 사용한 지도 좌표·노드·way 버전·변환행렬·검사 잔차가 있다. 손으로 고른 대응점의 타당성은 이미지와 지도에서 별도로 검토해야 하며, 계산을 재실행했다는 사실만으로 그 선택이 옳다고 증명되지는 않는다.

`source_page`의 PDF 이름은 이 문서의 원본 경로와 공식 공지로 해석한다. `map_evidence`의 상대 경로는 `data/` 기준이다. 원본 지도 응답은 `osm_raw.json`과 `osm_211_extension_raw.json`이며, 주소 검색이나 버스 CSV에서 좌표를 가져오지 않았다.

## 버스 데이터와 연결

버스 데이터의 운행 기준일은 2026-09-01, 버스 좌표 조회와 이번 지도 검토는 2026-10-21이다. 트램은 계획 도면의 위치이므로 현재 운행 중인 환승 정거장으로 취급하지 않는다.

트램 정거장 번호와 버스 정류장 ID는 다른 식별자다. 같은 이름으로 자동 연결하거나 트램 번호를 버스 노선 번호로 해석하지 않는다. 좌표가 빈 B·C 정거장은 거리 기반 연결에서 제외한다. A도 최근접 버스정류장을 찾은 뒤 도로의 어느 쪽인지, 진행 방향, 횡단보도와 실제 보행 접근점을 확인해야 한다. 승강장 영역 중심은 출입구가 아니므로 이 점 사이의 직선거리를 곧바로 환승 도보시간으로 사용하지 않는다.

기존 버스 CSV는 변경하지 않았다. 이번 결과는 전체 확대와 GitHub push 전 사용자 검토를 위한 로컬 시험본이다.
