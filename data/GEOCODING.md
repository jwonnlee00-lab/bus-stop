# 정류장 좌표 연결

기존 `bus_stops.csv`의 정류장을 대전광역시 버스정보시스템의 정류소정보조회 API로 조회하고, ID가 정확히 일치한 정류장에만 위도·경도를 추가한다. 원본 CSV의 행 순서와 컬럼 값은 유지하며 결과는 `bus_stops_geocoded.csv`에 저장한다.

## 공식 명세

출처는 [공공데이터포털의 대전광역시 정류소정보조회](https://www.data.go.kr/data/15157895/openapi.do)다. 확인한 Swagger 명세는 `sources/15157895.openapi.json`, 공개 설명 페이지는 `sources/station-info-page.html`에 보관했다.

`https://apis.data.go.kr/6300000/stationinfo/getStationByStopID`에 `BusStopID`와 `serviceKey`를 전달한다. 응답은 XML이며, 좌표 필드는 `GPS_LATI`(위도), `GPS_LONG`(경도)다. 7자리 `BUS_NODE_ID`와 5~6자리 `ARO_BUSSTOP_ID`(ARS ID)는 별개다. 기존 `sttn_id`와 `BUS_NODE_ID`를 문자열로 정확히 비교하며, ARS ID로 바꾸거나 이름·거리로 추정하지 않는다.

| 기존 ID | 정류장 | 반환 BUS_NODE_ID | ARS ID | 위도 | 경도 |
|---|---|---|---|---|---|
| 8001096 | 복합터미널 | 8001096 | 11830 | 36.349014 | 127.43567 |
| 8002159 | 아이빌딩 | 8002159 | 32190 | 36.351406 | 127.38061 |

두 정류장 모두 ID와 이름이 일치했다. 이는 시험한 두 ID의 연결을 확인한 결과이며, 모든 정류장 ID의 호환성을 의미하지 않는다.

## 결과 해석

기존 데이터의 운행 기준일은 2026-09-01이다. 새 API는 실시간 정보를 제공하며 과거 기준일을 지정하는 요청 변수가 없다. 검증 JSON의 `response_saved_at_range`는 XML 파일의 저장 시각 범위, `collected_at`은 보고서 생성 시각이다. 이번 응답은 2026-10-21 09:05~09:11 KST에 저장됐다. 파일을 복사하면 저장 시각이 달라질 수 있으며, 이 시간이나 좌표를 과거 운행 기준일의 위치로 해석하지 않는다.

CSV에 `latitude`, `longitude`, `geocode_status`, `api_stop_id`, `api_stop_name`, `ars_id`, `name_check`를 추가한다. 정류장이 조회되지 않거나 ID가 다르면 좌표를 비워 둔다. 이름이 달라도 ID가 정확히 일치하면 연결하되, `name_check=different`로 표시하고 검증 JSON에도 차이를 기록한다. 이름까지 정확히 일치하면 `exact`, 반환 이름이 없으면 `unavailable`이다. `matched`는 ID와 좌표 형식 검사를 통과했다는 뜻이며 이름이 다른 정류장의 실제 동일성까지 확정한 결과는 아니다.

| 상태 | 의미 |
|---|---|
| matched | ID가 정확히 일치하고 두 좌표가 유효함 |
| not_found | 결과가 없음. 실제 응답의 headerCd=4, itemCnt=0도 포함 |
| id_mismatch | 응답은 있으나 요청한 ID와 반환 ID가 다름 |
| ambiguous_id | 같은 ID가 여러 건 반환되어 하나를 선택할 수 없음 |
| missing_coordinates | 일치하는 ID는 있으나 좌표가 비어 있음 |
| invalid_coordinates | 숫자가 아니거나 0, 비유한 값, 위경도의 전세계 허용 범위 밖임 |
| api_error / request_error | API 오류 또는 통신 오류. 정류장이 없다고 판정하지 않음 |
| invalid_response / not_cached | XML 오류 또는 오프라인 실행에 필요한 응답 없음 |

좌표의 숫자 범위 검사는 위도 -90~90, 경도 -180~180을 사용한다. 이 검사만으로 대전 행정구역 내부 여부나 실제 정류장의 위치 정확성을 판정하지는 않는다.

## 재현 방법

프로젝트 루트에서 Python 3 표준 라이브러리로 실행한다.

```sh
python scripts/geocode_stops.py --run 20261021 --probe
python scripts/geocode_stops.py --run 20261021
python -m unittest discover -s tests -v
```

인증키는 `.env`에서 읽으며 출력하지 않는다. 응답 저장 전 인증키의 원문과 URL 인코딩 표현을 제거하고, 오류 로그에는 인증키가 포함될 수 있는 URL이나 예외 메시지를 쓰지 않는다. 원본 응답은 `raw/station_info/20261021/`에 정류장 ID별 XML로 저장한다. 같은 실행 이름으로 다시 실행하면 저장된 응답을 재사용한다. `--offline`을 추가하면 네트워크 요청 없이 저장된 XML만 읽는다.

출력 CSV가 이미 있으면 중단한다. `collect_bus.py`와 `verify_bus.py`는 기존 데이터에 쓰기 작업을 하므로 좌표 연결을 위해 실행할 필요가 없다.

## 검증 결과

2026-10-21에 기존 정류장 2,795개를 조회했다. 두 시험 정류장의 응답을 확인한 뒤 전체 조회를 수행했고, API의 결과 없음 응답을 반영한 파서로 저장된 XML 전체를 다시 읽어 최종 파일을 생성했다. 상세 수치와 실패 ID는 `geocoding_validation.json`에 보관했다.

| 항목 | 결과 |
|---|---:|
| 입력 및 출력 행 수 | 2,795 |
| ID 정확 일치 및 유효 좌표 | 2,568 (91.8784%) |
| 결과 없음 | 227 |
| 반환 ID 불일치 / 중복 ID 응답 | 0 / 0 |
| ID가 일치한 응답의 좌표 결측 / 유효성 오류 | 0 / 0 |
| 출력 위도 결측 / 경도 결측 | 각각 227 |
| 위도 범위 | 36.197227 ~ 36.49246 |
| 경도 범위 | 127.2478 ~ 127.53761 |
| ID·이름 모두 정확 일치 | 2,553 |
| ID 일치, 이름 차이 | 15 |

조회되지 않은 ID는 `29`로 시작하는 75개, `43`으로 시작하는 18개, `68`로 시작하는 134개다. API는 이들에 `headerCd=4`, `itemCnt=0`, “결과가 없습니다.”를 반환했다. ID 체계, 제공 범위, 데이터 시점 중 무엇이 원인인지는 확정할 수 없으며 다른 ID로 변환하지 않았다. `80`, `81`, `90`, `91`로 시작하는 나머지 ID는 모두 정확 일치로 연결됐다.

이름 차이 15개에는 공백·구두점 차이와 다른 명칭이 함께 포함된다. 예를 들어 `8005240`은 기존 명부의 “대전복합터미널”과 API의 “장재리(태련암입구)”가 다르다. 해당 좌표는 API가 같은 ID로 반환한 값이지만, 실제 같은 정류장인지는 별도 확인해야 한다. 원래 이름을 API 이름으로 덮어쓰지 않았다.

최종 CSV의 모든 기존 컬럼 값과 행 순서가 원본과 일치하며, `bus_stops.csv`의 수집 전후 SHA-256도 일치했다. 기존 데이터 5개 파일에 Git 변경이 없음을 확인했다. ID가 다른 동일 이름, 중복 ID, 빈 좌표, 잘못된 좌표, 결과 없음 및 API 오류를 다루는 오프라인 테스트 8개를 통과했다.
